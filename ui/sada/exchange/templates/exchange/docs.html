Documentation

A quick tour of this proof of concept and how it maps to the real system.

What it does today

  • No sign-on. A fictitious profile is created per visit and you're addressed by name.
  • Chat interface with history per profile — producer, consumer, or supplier.
  • Regional inquiry log of recent (aggregated, fictitious) concerns.
  • Voice in and out: speak your concern (browser speech recognition) and have answers read aloud (speech synthesis). Both degrade gracefully if unsupported.
  • Multilingual: {{ languages.values|join:", " }}. Output translates to the chosen language.
  • Clear chat removes your transcript and gives you a fresh profile.

Guardrails and tone

  • Out-of-scope asks get a gentle redirect, not an answer.
  • Personal contact details are flagged for human review, never redacted — authentic voice matters.
  • Every answer is phrased as a suggestion, never a command, and ends by handing the decision back.
  • Each answer carries citations: regional data, a peer example, and a standard clause.
  • Alternative follow-up questions are offered to keep it simple and quick.

The mock API

The browser calls POST /api/chat with { message, language, profile } and receives { text, citations[], suggestions[], pii_flagged[], in_scope, language }. The response is produced by a deterministic engine today. To go live, swap the single engine.respond() call for the real Fair Exchange runtime — the request and response shapes are intentionally close to it, so the UI does not change.

How it maps to the target

  • Model access is designed to go through Amazon Bedrock (never a third-party model API), using credentials from .env. Set USE_BEDROCK=1 to enable the live path.
  • The real agent is a Strands agent on Amazon Bedrock AgentCore, with Bedrock Guardrails as the governance layer.
  • Scope is enforced in tools from session context; the model cannot supply another producer's ID.
